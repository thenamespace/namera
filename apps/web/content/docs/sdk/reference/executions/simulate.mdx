`namera.executions.simulate(request)` does not sign, submit, or sponsor an operation.

## Usage

Install `viem` for `parseEther`. Replace the example IDs and recipient.

```ts title="index.ts"
import { NameraClient, type SimulateExecutionRequest } from "@namera-ai/sdk";
import { parseEther } from "viem";

const namera = new NameraClient({ apiKey: process.env.NAMERA_API_KEY! });

const request = {
  namespace: "eip155",
  walletId: "0199dfe1-0000-7000-8000-000000000001",
  sessionKeyId: "0199dfe1-0000-7000-8000-000000000002",
  chainId: "eip155:84532",
  calls: [
    {
      to: "0x2222222222222222222222222222222222222222",
      value: parseEther("0.001"),
      data: "0x",
    },
  ],
} satisfies SimulateExecutionRequest;

const simulation = await namera.executions.simulate(request);
if (!simulation.success) throw new Error(simulation.error.message);

console.log(simulation.data);
```

## Parameters

`request` is a `SimulateExecutionRequest`. It has no `sponsor` parameter.

Returns a promise containing a [NameraResult](/docs/sdk/handling-results-and-errors).
The fields below describe successful `data`. JSON values are illustrative;
SDK timestamps are decoded date-time values and bigint fields are decimal strings in JSON.

Both `callsSucceeded` and `allowed` must be true before proceeding. A denied policy decision can still be a successful SDK response.

## Errors

Execution, authorization, and network failures return `success: false`. See [Handling Results and Errors](/docs/sdk/handling-results-and-errors)
for authentication, transport, and contract errors.
