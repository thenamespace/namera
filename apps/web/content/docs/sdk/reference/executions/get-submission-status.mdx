`namera.executions.getStatus(submissionId)` tracks a submission before and after confirmation.

## Usage

Install `@namera-ai/sdk` and set `NAMERA_API_KEY`. Replace example IDs with resources available to your credential.

<Tabs items={["index.ts", "client.ts"]}>
<Tab value="index.ts">

```ts title="index.ts"
import { namera } from "./client";
const result = await namera.executions.getStatus("0199dfe1-0000-7000-8000-000000000003");
if (!result.success) throw new Error(result.error.message);

console.log(result.data);
```

## Returns

<include>../../../../snippets/sdk/result.md</include>

- **`namespace`** (`"eip155"`): Chain namespace.
- **`submissionId`** (`string`): Requested submission UUID.
- **`status`** (`"reserved" | "prepared" | "submitted" | "confirmed" | "failed"`): Discriminator for the response shape.
- **`userOperationHash`** (`` `0x${string}` | null ``): Present only for reserved, prepared, and submitted.
- **`execution`** (`ExecutionResponse`): Complete confirmed execution record. Present only for confirmed.

## Parameters

### submissionId

- **Type:** `string`
- **Required**

The `submissionId` returned by `execute()`. Save it to resume tracking after a restart. It is neither the confirmed execution ID nor an onchain transaction hash.

```ts title="index.ts"
import { namera } from "./client";
const result = await namera.executions.getStatus("0199dfe1-0000-7000-8000-000000000003"); // [!code focus]
if (!result.success) throw new Error(result.error.message);

console.log(result.data);
```

## Polling

Check the same submission while its status is `reserved`, `prepared`, or `submitted`. Stop on `confirmed` or `failed`. This method performs one read; it does not poll automatically. Do not call `execute()` again to check progress.

## Errors

`EXECUTION_SUBMISSION_NOT_FOUND` means the submission is missing or unavailable to your credential. See [Handling Results and Errors](/docs/sdk/handling-results-and-errors) for shared authentication, transport, and contract errors.
