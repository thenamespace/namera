## Sign In with Your Browser

```sh
namera login
```

Approve the connection and select active session keys in the browser. If the
browser does not open, use the verification URL and code printed in the terminal.
The command waits for approval and saves credentials in your OS keyring.

<include>../../snippets/cli/output/login.md</include>

Use a named connection for another workspace:

```sh
namera login --profile work --device-name "Work laptop"
namera auth status --profile work
```

The CLI refreshes saved OAuth credentials when possible. If a connection expires
or is revoked, sign in again with the same profile.

## Use an API Key

Set `NAMERA_API_KEY` through your shell's secret manager or CI secret store, then:

```sh
namera auth status
```

<include>../../snippets/cli/output/auth-status.md</include>

An API key takes precedence over saved CLI credentials, even when you pass
`--profile`. Unset it to return to browser-based login:

```sh
unset NAMERA_API_KEY
namera auth status --profile personal
```

Do not put the key in command arguments, source files, or logs.

## Review Access

```sh
namera session-key list
namera session-key get
```

Authentication identifies the caller. Grants select usable session keys;
installed permissions and policies restrict what those keys can do. Individual
operation flags also need account and session-key read access to validate selections.

## Sign Out

```sh
namera logout --profile personal
```

<include>../../snippets/cli/output/logout.md</include>

Logout removes the saved CLI connection on this device. It does not delete
imported keys or revoke the authorization on the server. Revoke that authorization
in the dashboard to end its server-side access.

MCP has [separate credentials](/docs/cli/reference/mcp/login). Ordinary login and
`NAMERA_API_KEY` do not authorize an MCP client.
