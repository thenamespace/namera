# @namera-ai/contracts

ABIs, CREATE2 addresses and deployment provenance of Namera's Smart Sessions contracts: `SmartSession`,
`ECDSASessionValidator`, `WebAuthnValidator`, `SessionHook` and the policies (`AllowPolicy`, `ArgPolicy`,
`ApprovalPolicy`, `SpendPolicy`, `ValuePolicy`, `RateLimitPolicy`, `GasPolicy`, `SignaturePolicy`). No runtime
dependencies: every export is generated data.

> **Unaudited release candidate.** The contracts have had internal security reviews only, no external audit, and
> there is no bug bounty yet. Report vulnerabilities as [`SECURITY.md`](../../SECURITY.md) describes.

## Install

The release candidate is published under the `rc` tag.

```sh
pnpm add @namera-ai/contracts@rc
```

## Supported

- **Account:** Kernel 3.3 on EntryPoint v0.7, deployed or through EIP-7702. Smart Sessions and `SessionHook` refuse to
  install on any other account.
- **Chains:** every contract is deployed and verified (Sourcify and Etherscan) at the same address on Base (8453),
  Sepolia (11155111), Base Sepolia (84532), Arbitrum Sepolia (421614) and OP Sepolia (11155420). `deployments` lists
  exactly these chains.

## Usage

Each contract is a namespace with one export per version. A version has the same address on every
chain; `deployments` holds its provenance per chain id.

```ts
import { SmartSession } from "@namera-ai/contracts"
import { encodeFunctionData, pad } from "viem"

const removeSessionCall = encodeFunctionData({
  abi: SmartSession.v1.abi,
  functionName: "removeSession",
  args: [pad("0x01", { size: 32 })]
})

SmartSession.v1.address // "0x26e62071c25F003BA503898e0d716Cd98CEF6e80"
SmartSession.v1.deployments[8453]?.blockNumber // its creation block on Base
```

Each part of a version is also its own export: `abiV1`, `errorsV1` (the ABI's error fragments), `addressV1` and
`deploymentsV1`, which `v1` is built from. Import them from the contract's subpath when bundle size matters: esbuild
keeps a whole object, or a whole namespace re-exported from the package root, once any property of it is used.

```ts
import * as SmartSession from "@namera-ai/contracts/SmartSession"

SmartSession.addressV1 // "0x26e62071c25F003BA503898e0d716Cd98CEF6e80", without the ABI
```

`Contract.Version`, `Contract.Deployment` and `Contract.Compiler` type the generated values.

`External` holds the addresses of the contracts Namera builds on but does not deploy, by version: EntryPoint 0.7 and
the supported smart accounts' factories, implementations and validators.

```ts
import { External } from "@namera-ai/contracts"

External.kernel["3.3"].factory // "0x2577507b78c2008Ff367261CB6285d44ba5eF2E9"
```

## How it is generated

`src/` is generated by `pnpm contracts:generate` (`node scripts/bin.ts contracts generate`) from the Foundry
build, `contracts/script/config/external.json` and the deployment records in [`contracts/deployments/`](../../contracts/deployments); never
edit it by hand. `pnpm check` runs `pnpm codegen:check` (`contracts generate --check`), which fails when the
committed sources are stale or a record sits at another address than the current build deploys to.
